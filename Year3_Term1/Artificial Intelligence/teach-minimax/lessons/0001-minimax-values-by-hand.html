Lesson 1 · CS420 Adversarial Search

Minimax values, by hand

The win for today: fill in every node of an exam-style game tree correctly, first try, in under three minutes.

The one idea

Two players alternate. MAX ▲ wants the utility as high as possible; MIN ▼ wants it as low as possible. Both are assumed to play optimally.[slide 16] So the value of a node is:

leaf → its utility (already given)
▲ node → max of its children
▼ node → min of its children

You compute it bottom-up: values are “backed up” from leaves to the root as the recursion unwinds.[slide 18] The root’s best move is the child whose value equals the root’s value.

Worked example

The classic two-ply tree from the slides and AIMA Fig. 5.2.[slide 19] Bottom row of ▼ nodes: min(3,12,8)=3, min(2,4,6)=2, min(14,5,2)=2. Root ▲: max(3,2,2)=3. MAX plays the left move a₁; MIN replies b₁.

Exam habit: write each backed-up value next to the node, row by row, deepest row first. Never compute a node before all its children have values.
