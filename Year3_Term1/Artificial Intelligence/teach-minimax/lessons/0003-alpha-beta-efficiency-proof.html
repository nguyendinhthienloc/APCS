Part A: α-β returns the same value as minimax

Claim. A branch pruned by α-β can never change the value at the root.

Proof (MIN-node case). Suppose a ▼ node n prunes because its current value v ≤ α. Here α is a value that some ▲ ancestor of n can already guarantee through another move. MIN can only lower v by looking at more children, so the exact value of n is ≤ v ≤ α. That ancestor ▲ therefore never strictly prefers the move leading to n, and the exact value of n can’t change the ancestor’s choice or value. The ▲ case is symmetric: v ≥ β means a ▼ ancestor already has an option ≤ β and won’t let play reach here. By induction up the tree, the root value is unchanged. ∎

Slide 29 shows the same thing with algebra: max(3, min(2, x, y), 2) = 3 for any x, y, because min(2, x, y) ≤ 2.[slide 29]

Part B: counting leaves with perfect ordering

Assume the best child is always searched first, with uniform branching factor b and depth m. Each node in the search has one of three jobs:

TypeIts jobWhat it must search
1 · exactfind its exact value (the root, and the best line)first child: type 1; other b−1 children: type 2
2 · cutshow “this is no better than what you already have”one child (the best one refutes it immediately), which is type 3
3 · allshow “none of my moves is good enough”all b children, each type 2

Let T₂(d) and T₃(d) be the leaves examined below a type-2 or type-3 node of height d (a leaf has height 0, and T₂(0) = T₃(0) = 1):

T₂(d) = T₃(d−1)          (search one child)
T₃(d) = b · T₂(d−1)      (search all b children)
⇒ T₂(d) = b·T₂(d−2)  ⇒  T₂(d) = b^⌊d/2⌋,   T₃(d) = b^⌈d/2⌉

Cut and all levels alternate: every other level branches b ways, and the levels in between branch only once. That alternation is the whole reason for the m/2.

Adding up the exact line (the root’s best path plus the b−1 cut siblings at each level) gives the classic result of Knuth & Moore:[Knuth & Moore 1975]

leaves examined = b⌈m/2⌉ + b⌊m/2⌋ − 1 = O(bm/2)

Check with the tree from slide 28 (b = 3, m = 2): 3 + 3 − 1 = 5. If D’s best child (2) came first, you’d search B’s 3 leaves, then 1 leaf each in C and D.[AIMA §5.2.4]

What it means

Perfect orderingO(bm/2): effective branching factor √b (chess: about 6 instead of 35), so you can search twice as deep in the same time
Random orderingabout O(b3m/4) for moderate b
Worst orderingO(bm), no better than minimax but never worse
In practicePerfect ordering is impossible (it would already need the best move), but killer moves, iterative deepening and transposition tables get close[slides 31–32]

Exam answer skeleton

1. Correctness: pruned branches satisfy v ≤ α (or v ≥ β), so they can’t affect the ancestor’s choice. The root value equals minimax.
2. Best case: with perfect ordering, nodes alternate between “search 1 child” and “search all b”. T(d) = b·T(d−2) ⇒ b⌈m/2⌉+b⌊m/2⌋−1 = O(bm/2).
3. Compare: minimax O(bm). Effective branching √b, so twice the depth in the same time. Random O(b3m/4), worst O(bm).
