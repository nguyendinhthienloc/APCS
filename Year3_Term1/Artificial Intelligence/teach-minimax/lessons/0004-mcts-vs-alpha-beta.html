Monte Carlo tree search vs alpha-beta

The win for today: given a true/false statement comparing MCTS and α-β, answer it and give the one-line reason the examiner wants.

The story

You’re choosing between three restaurants in a city you don’t know, and nobody can give you a reliable rating. α-β would need that rating, which is the evaluation function. Without one, you just try them: eat at each a few times and keep count of how often you leave happy. You go back more to the ones that seem good (exploitation), but now and then you try the one you’ve barely visited, because it might be great (exploration).

That’s MCTS. It doesn’t estimate how good a position is. It plays the game out to the end many times and averages the results. Who won is decided by the rules of the game, not by a guess.[AIMA §5.4]

The four steps, repeated until time runs out

1. SelectionFrom the root, walk down the tree using a selection policy (UCT) until you reach a leaf of the tree.
2. ExpansionAdd a new child node to that leaf.
3. SimulationPlay out (also called a rollout) from the new node to the end of the game, choosing moves with a playout policy. These moves are not stored in the tree.
4. Back-propagationUpdate wins and playout counts on every node back up to the root.

At the end, return the move with the most playouts, not the one with the highest win rate. 65/100 is more trustworthy than 2/3.

UCB1: the selection rule

UCB1(n) = U(n)/N(n)  +  C · √( ln N(parent) / N(n) )
exploitation (average win rate)  +  exploration (large when n has been tried only a few times)

Where each one wins

the branching factor is huge (Go: 361), so α-β can only look 4–5 ply deepthe branching factor is low (chess: about 35)
a good evaluation function is hard to write, or the game is brand-new (MCTS only needs the rules)a good evaluation function exists
