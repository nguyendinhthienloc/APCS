Alpha-beta pruning

The win for today: trace α-β by hand and mark exactly which branches get pruned. Exam question type: Quiz 02, slide 33.

Back to the boxes

Same game as before: you (▲) pick a box, your opponent (▼) picks which envelope you get.

Box L: $3, $12          Box R: $2, ?, ?

You open Box L and see that it guarantees you $3. Then you open Box R and the first envelope you see is $2.

Stop. Whatever is in the other envelopes, your opponent can always hand you that $2, so Box R is worth at most $2. You already have $3 from L, so you will never choose R. You don’t need to look at the rest of R.

That’s alpha-beta pruning: skip branches that can’t change the decision. You get the same answer as minimax with less work.[slide 26]

The two numbers

As you walk down the tree, you carry two numbers along the path:[slide 27]

α (alpha)the best score MAX can already guarantee somewhere on the path. Starts at −∞ and only goes up.
β (beta)the best score MIN can already guarantee somewhere on the path. Starts at +∞ and only goes down.

In the boxes: after Box L, α = 3. Inside Box R, MIN’s v drops to 2 ≤ α, so you prune.

The procedure

1. Start at the root with α = −∞, β = +∞. Explore children left to right, depth-first.
2. Pass α and β down to each child unchanged.
3. When a child returns, update the node’s value v:
  ▲ v = max(v, child), then α = max(α, v). Prune if v ≥ β.
  ▼ v = min(v, child), then β = min(β, v). Prune if v ≤ α.
4. Return v to the parent. Only v goes back up; α and β don’t.

This follows the pseudocode on slide 30 (AIMA Fig. 5.7). Note the ≥ / ≤: ties prune too.

A memory hook: ▲ watches β, ▼ watches α. Each node checks the bound set by the other player higher up, because that player will refuse to let the game come here.
