Minimax cheat sheet

Rule

NodeValue
Terminal / leafUTILITY(s) — given
▲ MAXmax of children
▼ MINmin of children

Compute bottom-up. Best move at root = child whose value equals root value.

Pseudocode (slide 20 / AIMA Fig. 5.3)

MINIMAX-SEARCH(game, s):  v, move ← MAX-VALUE(game, s); return move

MAX-VALUE(game, s):
  if IS-TERMINAL(s): return UTILITY(s, player), null
  v ← −∞
  for a in ACTIONS(s):
    v2, _ ← MIN-VALUE(game, RESULT(s, a))
    if v2 > v: v, move ← v2, a
  return v, move

MIN-VALUE: same, with v ← +∞ and "v2 < v", calling MAX-VALUE.

Properties (slide 22)

CompleteYes, if tree is finite
OptimalYes, against an optimal opponent
TimeO(bm)
SpaceO(bm) — depth-first
Suboptimal MINMAX does at least as well (slide 21)

Alpha-beta pruning (slides 26–31)

αMAX’s guaranteed best on the path. Starts at −∞, only rises.
βMIN’s guaranteed best on the path. Starts at +∞, only falls.
▲ after each childv = max(v, child); α = max(α, v); prune if v ≥ β
▼ after each childv = min(v, child); β = min(β, v); prune if v ≤ α
Passingα, β go down; only v comes up. Children left to right.
Hook▲ watches β, ▼ watches α. Ties prune.
ResultSame root value and move as minimax.
TimePerfect ordering O(bm/2); random O(b3m/4); worst case O(bm)

Proof of α-β efficiency (exam Q2.1)

CorrectnessPrune only when v ≤ α (▼) or v ≥ β (▲). The node’s exact value can only move further in that direction, and an ancestor already has an option at least as good. So the root value equals minimax.
Node typesexact: 1 exact child + (b−1) cut children · cut: 1 child (all-type) · all: b children (cut-type)
RecurrenceT(d) = b·T(d−2) ⇒ leaves = b⌈m/2⌉ + b⌊m/2⌋ − 1 = O(bm/2) (Knuth & Moore 1975)
MeaningEffective branching factor √b ⇒ twice the depth in the same time. Random ordering O(b3m/4); worst O(bm).

MCTS vs α-β (AIMA §5.4, exam Q2.2)

LoopSelection (UCT) → Expansion → Simulation (playout) → Back-propagation. Return the move with the most playouts.
UCB1U(n)/N(n) + C·√(ln N(parent) / N(n)). C ≈ √2 in theory; larger C = more exploration.
MCTS winshuge b (Go) · no good eval function · new game, rules only · robust (averages many playouts) · playout cost O(depth)
α-β winslow b plus good eval (classic chess) · single critical move or trap · “obvious” wins that take long playouts to confirm
